## Frozen decisions applied

- **C1:** `providerHostPrestartEnabled` requires `warm-pool`, Provider Host v2, and an empty
  `CgroupV2Root`. Protected cgroup-v2 workers retain the existing post-claim spawn path.
- **C2:** the prestart path creates FD 3 before spawn, but its unbuffered handoff waits for adoption.
  Adoption sends the already-resolved `RunnerCredential`; cancellation/abort closes the write end
  without encoding. The normal path also continues to resolve credentials in `runExecution` and now
  starts its writer only after process spawn.
- **C3:** prestart process-tree options use a stable SHA-1 UUID derived from the worker instance and
  `synara-provider-prestart`, generation 1. No cgroup rename is attempted.
- **C4:** one manager slot owns at most one live prestarted process. Parent cancellation, daemon exit,
  mismatch, and failed handoff terminate via `providerHostV2Process.abort`; unexpected exits are
  cleaned before sequential retries, bounded to three attempts with the existing 100ms/200ms pattern.
- **C5:** adoption looks up the claimed provider's cached descriptor and runs the exact current
  workload validation before credential delivery. Missing/unavailable/mismatched hosts are killed and
  use `startProviderHostV2` plus the normal Describe path. One bounded structured line records
  `adopted`, `descriptor-mismatch`, `not-ready`, `retries-exhausted`, or another fixed outcome.
- **C6:** both adopted and post-claim paths call `configureProviderHostV2ForExecution`, which contains
  the pre-existing descriptor checks, Runtime Event negotiation, and negotiated size limits. The
  adopted path does not send a second Describe.
