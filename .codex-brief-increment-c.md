## Goal

Remove the Provider Host cold-start segment from the claim critical path: a warm-pool agentd worker
starts its Provider Host process and completes `Describe` BEFORE claiming, then adopts that live
process at claim time by lazily delivering the credential over the already-open FD 3.

## Current behavior (verified anchors)

- Host starts strictly after claim: `internal/agentd/daemon.go:160` (Claim) → `:238`
  (`runExecution`) → `internal/agentd/runner.go:109-118` (`RunControlled`) →
  `internal/agentd/provider_host_v2.go:228-290` (`runProviderHostV2`), spawn at `:236`
  (`startProviderHostV2`), Describe at `:255`, StartSession at `:282`.
- Credential is delivered via FD 3 with a goroutine that writes lazily AFTER spawn
  (`provider_host_v2.go:971-989`, `SYNARA_PROVIDER_CREDENTIAL_FD=3`).
- A credential-free start path already exists and is exercised pre-registration:
  `describeProviderHostV2` (`provider_host_v2.go:193-226`) calls `startProviderHostV2(ctx, nil, ...)`;
  `CapabilitySummary` runs it at `daemon.go:101-103`.
- Worker mode: `internal/agentd/config.go:253-283` (`effectiveWorkerMode`,
  `SYNARA_AGENTD_WORKER_MODE`); warm/pinned workers exit after one attempt (`daemon.go:255-260`).
- Process-tree/cgroup naming takes `(executionID, generation)` (`runner.go:74`
  `processTreeOptions`); the probe uses a synthetic execution ID (`runner.go:92`).

## Frozen design decisions

- C1 (scope): pre-start ONLY when `effectiveWorkerMode == warm-pool` AND the protected cgroup-v2
  supervisor is NOT configured (no `SYNARA_AGENTD_CGROUP_V2_ROOT`). Kubernetes warm Pods are the
  target; the protected-supervisor rename problem is explicitly out of scope for v1 and must fall
  back to the current post-claim spawn.
- C2 (credential): pre-spawn with the FD-3 pipe created but UNWRITTEN. Restructure the lazy write so
  the credential bytes can be supplied after spawn (e.g. the write goroutine blocks on a channel that
  adoption fills). A pre-started host that is torn down before adoption must close the pipe without
  writing. Credential material must never be buffered in the daemon longer than the existing
  post-claim path does today (resolve credential at claim exactly as now, then hand to the adopter).
- C3 (naming): the pre-started host uses a synthetic prestart execution identity (same pattern as the
  probe's `providerProbeExecutionID`) for its process-tree options. Since C1 excludes the protected
  supervisor, no cgroup rename is needed; the plain process-group scope is identity-agnostic.
- C4 (lifecycle): at most ONE pre-started host per daemon (warm workers run one attempt then exit).
  Kill and clear it on: drain signal, daemon exit, adoption failure, or unexpected process exit
  (respawn with the existing backoff pattern, bounded retries). Reuse the existing managed
  process-scope termination helpers — never leak a host process.
- C5 (adoption safety): at claim, adopt only when the pre-started host's validated Describe result is
  compatible with the claimed workload exactly as the current post-claim validation would require
  (provider available/version-compatible, protocol major, runtime event range, credential delivery
  mode, resume strategies). On ANY mismatch or any adoption error: kill the pre-started host and fall
  back to the normal spawn path silently and correctly. Fallback must be indistinguishable from
  today's behavior. Log one bounded line on adopt vs fallback (no new metrics in this increment; the
  cold-start tier percentiles already measure the win).
- C6 (Describe reuse): the adopted path reuses the live host's Describe result instead of issuing a
  second Describe; validation logic must remain the byte-identical checks used today (extract/shared
  helper rather than duplicating).
