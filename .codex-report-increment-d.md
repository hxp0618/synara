## Frozen decisions applied

- **D1 — revocation gate unchanged:** `resolveWorkspaceGitCredentialStage(..., "git_fetch", ...)` still runs before
  `Materialize`. Resolve failure follows the existing `credential_invalid` workspace failure path and never invokes
  cache materialization. The focused daemon test uses a transport stub to prove this order without a network listener.
- **D2 — bounded freshness:** window `0` always foreground-Fetches. A positive value skips only when the exact
  fingerprint cache is structurally valid, its marker age is in `[0, window)`, the default remote ref resolves, and
  the required restore object resolves. Every missing, stale, future, unparsable, invalid, or corrupt case falls back.
- **D3 — marker:** `last-successful-fetch` contains one UTC RFC3339Nano timestamp, is read/written only under the
  repository cache lock, and is installed via mode-`0600` temp file + sync + rename. No URL or Credential is stored.
- **D4 — background refresh:** a skip creates one internal refresh closure. After `workspace.ready`, daemon transfers
  the already-resolved short-lived Credential to a goroutine which takes the cache lock, performs the same Fetch,
  updates the marker, logs a bounded failure, and cannot change the running Turn result.
- **D5 — visibility:** Repository materialization emits exactly one structured outcome from
  `fetched | cache-fresh-skip | fallback-after-skip-doubt`; fingerprint and background error text are bounded.
- **D6 — contract:** the cache layout, preparation order, Repository network policy, revocation authority, marker,
  fallback rule, bounded window, background behavior, and no-wire-change boundary are updated.

## Risks / deferred edges

- The full agentd suite still needs one run in an environment that permits loopback listeners. The failure above is
  from a pre-existing Checkpoint test before the suite can finish; all Increment D focused tests pass without a
  listener.
- Foreground marker-write failure deliberately does not fail a successfully fetched Turn, preserving window-`0`
  behavior. It leaves the prior/missing marker in place, so the next Claim fails safe to another foreground Fetch.
  Background marker-write failure is reported as the bounded background-refresh warning.
- An abrupt process death between temp-file creation and rename can leave an inert `.fetch-marker-*` file. It contains
  only a timestamp, is never treated as authoritative, and can be cleaned by a later cache-maintenance increment.
- Cross-worker wall-clock skew fails safe: a future marker is doubt and forces a foreground Fetch. No distributed
  monotonic-clock claim is made.
